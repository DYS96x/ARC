# STD_010 — Documentation

Version: 1.0.0  
Status: Draft  
Authority: HOLY ARC Laws  
Classification: Internal

---

# Standard

> Every ARC capability shall maintain clear, accurate and discoverable documentation that preserves understanding, decisions, context and institutional memory.

Documentation is how knowledge survives beyond individuals.

---

# Purpose

Define how ARC creates, maintains and governs documentation.

Documentation exists to preserve:

- Understanding
- Decisions
- Architecture
- Responsibilities
- History
- Learning

# Documentation Principles

## D001 — Documentation Has Purpose

Every document must answer:

- Why does it exist?
- Who uses it?
- What decision or understanding does it preserve?

Documentation without purpose creates noise.

---

## D002 — Single Source Of Meaning

Important concepts should have one canonical location.

Copies may exist for convenience.

The authoritative source must remain clear.

---

## D003 — Discoverability

Documentation should be easy to find.

Organisation should follow meaning, not storage convenience.

Users should navigate through understanding.

---

## D004 — Accuracy

Documentation should represent reality.

When documentation and reality conflict:

Reality wins.

Documentation must be updated.

---

## D005 — Context Preservation

Important documentation should include:

- Purpose
- Scope
- Owner
- Relationships
- Decisions
- Constraints
- History

Context prevents misunderstanding.

---

## D006 — Decision Records

Important decisions should preserve:

- Decision
- Date
- Owner
- Evidence
- Alternatives considered
- Reasoning
- Outcome

Decisions without history lose institutional knowledge.

---

## D007 — Versioning

Documentation changes should preserve:

- Previous versions
- Change reason
- Author
- Date
- Impact

History must remain accessible.

---

## D008 — Naming Standards

Documentation should use consistent naming.

Names should communicate:

- Purpose
- Type
- Scope
- Version where required

Naming should reduce cognitive load.

---

## D009 — Living Documentation

Documentation should evolve with:

- Systems
- Architecture
- Knowledge
- Reality

Documentation is maintained, not created once.

---

## D010 — Documentation Quality

Good documentation is:

- Clear
- Accurate
- Relevant
- Discoverable
- Maintained
- Connected

# Documentation Quality Tests

Documentation passes when:

- Purpose is clear.
- Ownership exists.
- Information is accurate.
- History is preserved.
- Relationships are documented.
- Users can discover it.

---

# Violations

The following violate this standard:

- Undocumented critical systems.
- Missing ownership.
- Outdated documentation.
- Hidden decisions.
- Conflicting canonical sources.
- Erased history.
- Documentation disconnected from reality.
